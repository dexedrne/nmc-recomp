# KHNMC Win64 runtime v0 and headless boot (batch A2)

Hand-written runtime for the lifted `kh2fm.exe` (route B). Our own code; it contains no game data. Lifted C, snapshots and traces are game-derived and stay in
`out/`, `work/` and on build-host. Scale is stated as counts only.

Result: the lifted program, linked with this runtime, boots headless on build-host through the whole CRT start-up (3 `__xi` + 4,653 `__xc` constructors, WinMain,
`axaAppMain`), through a native-shell replacement of the CLR `ManageRun`, into `GXDevice.init`, `createDevices` (0x124060) and the D3D12 device creation, starts the
two game threads, and then idles in the game's own package-file wait because the package `.hed` files are not there (file layer = next batch).
Independent check: a Unicorn emulation of the ORIGINAL bytes matches the lifted run on 1,677 consecutive import calls and on all 9,335 pages of .data/.bss/.shared/heap.

## Build and run

```
# 1. lifted shards (lifter's output; compiled once, ~1,731 CPU-seconds, peak 379 MB per translation unit, 117 TUs):
build-host:~/khnmc-work/rt/lifted/{shards,gen,rt}   libkh2lifted.a via: python3 tools/buildgen.py --root . ; ninja -f build.x86.ninja -j9 lib/x86/libkh2lifted.a
# 2. runtime + link (seconds):
tools/remotebuild.sh                      # rsync to build-host, make -j8 -> ~/khnmc-work/rt/khnmc (40.7 MB, -rdynamic so host backtraces name f_<rva>)
# 3. run:
tools/remoterun.sh trace.txt KH_RUN_SECONDS=20          # env on build-host: KH_EXE KH_ROOT KH_DOCS are set by the script
./khnmc --selftest                                    # allocator, qsort/bsearch (MS algorithm), printf engine, CS, fibers incl. migration to another thread, yield hooks
```

Environment: `KH_EXE` (default pc/kh2fm.exe), `KH_ROOT` (the Windows "game directory", `C:\KH2`), `KH_DOCS` (stands in for `Documents`), `KH_TRACE=file`
(one line per import call: `seq tTID dll!name(rcx,rdx,r8,r9) <- call-site-RVA`), `KH_TRACE_MAX=n`, `KH_TRACE_NOSYNC=1`, `KH_STOP_AT_GX=1` (exit at the first import called from
the GX extent), `KH_RUN_SECONDS=n` (the shell ends the run), `KH_DUMP_THREADS=1` (guest stack scan of every thread at exit), `KH_LOG_COM=1` (every COM call of the null backends),
`KH_VERBOSE=1`, `KH_ENTRY=crt|winmain|axa|ADDR`, `KH_WIN=WxH`. Oracle mode: `KH_DET=1 KH_SNAPSHOT=prefix KH_STATE_DUMP=file`.
`tools/arm64check.sh` compiles every runtime source with clang for arm64 on the Mac mini (windowless, nice, one file at a time, deletes its directory afterwards); all 18 sources pass in bias mode.

## Address model and loader (`loader.c`)

* One `MAP_FIXED_NOREPLACE` mapping of 12 GiB (lazily committed) at **0x140000000** holds the PE image at its preferred base (no relocation) followed by the guest arena (heap, thread and
  fiber stacks, VirtualAlloc-style page runs). Section raw data is copied, BSS is the zero mapping, the IAT slots receive `0x7ff7f0000000 + 16*i` in `kh_import_table` order (= PE import order),
  the TLS template/index/callbacks come from the PE TLS directory. TLS callbacks run with `DLL_PROCESS_ATTACH` (and `THREAD_ATTACH/DETACH` per thread), then the **native CRT entry
  0x4393d0** (`WinMainCRTStartup`) is called as lifted code: that is exactly what the CRT does (security cookie, `__isa_available_init` with the fixed CPUID profile, `_initterm_e` over 3 `__xi`,
  `_initterm` over 4,653 `__xc`, WinMain 0x143720 -> function pointer 0x62ba70 = `axaAppMain` 0x14f1e0). The loader's `_initterm`/`_initterm_e` are the runtime's own imports and count the entries run.
* **Fallback bias mode** (`-DKH_XLATE_MODE=2`): map the same region anywhere, `gs_bias = host - 0x140000000`; guest addresses (vtables, saved pointers, IAT values) never change, so no relocation is
  needed and every host access goes through `XL(g, a)`. Compile-checked for arm64 (macOS clang); not run.
* Guest memory the runtime hands out (malloc family, HeapAlloc, stacks, fiber blocks, COM objects) comes from the guest arena (`core.c`: size classes <= 256 KiB, page runs above, 16-byte
  headers, aligned blocks, `ga_deterministic` bump mode for the oracle), so the same code works with a bias.
* Threads (`threads.c`): each guest thread = pthread (48 MiB host stack) + own `KCtx` + 2-8 MiB guest stack + a 4 KiB TEB-like block (gs base; `[0x30]` self, `[0x58]` TLS array pointer,
  `[0x08]/[0x10]` stack limits) + a 160-byte TLS block seeded from the template. All 169 `gs:` uses in the lifted code are `gs:[0x58]`.

## Services (what is real, what is a stub)

Import status per import with call-site counts: `out/import_status.tsv` (generated by `tools/import_status.py` from the linked binary and IMPORT-CENSUS.md).
**368 imports: 337 implemented in 7,426 of 7,785 call sites; 31 are named fatals in 359 sites** (gdi32 x10 = 296 sites in the dev-only debug-draw classes, hid x10 = 62 sites that are
unreachable without a HID device, `SetupDiGetDeviceInterfaceDetailW` x2, and 10 imports with 0 sites). A fatal prints `unimplemented import DLL!Name called (call-site RVA 0x..., rcx..r9)`, the last 30 import
calls, a guest return-address scan and a host backtrace, then exits (`kh_fatal`); there is no silent `return 0` default.

### D3D12 null device (`null_d3d12.c`)

Generic COM machinery in `com.c`: a class = one vtable of distinct synthetic host-function addresses (so `call [vtable+slot*8]` reaches the handler through `kh_dispatch`), objects are guest
blocks `{vtbl, class id, refcount, extra}`; per-slot counters are printed at exit. Implemented slots (called during init, with counts from a 30 s run): `IDXGIFactory4` MakeWindowAssociation, EnumAdapters1,
CreateSwapChainForHwnd; `IDXGIAdapter3` EnumOutputs, GetDesc1 (VendorId 0x106b), QueryVideoMemoryInfo; `IDXGIOutput` GetDesc, **WaitForVBlank (not in the shim spec; the present thread calls it every frame, paced at 60 Hz)**;
`IDXGISwapChain3` GetBuffer, GetContainingOutput, GetDesc1, GetFullscreenDesc, SetMaximumFrameLatency, GetFrameLatencyWaitableObject (a signalled manual-reset event), GetCurrentBackBufferIndex, Present(1), ResizeBuffers, GetDesc;
`ID3D12Device` CreateCommandQueue, CreateCommandAllocator, CreateGraphicsPipelineState, CreateCommandList, CheckFeatureSupport (multisample levels), CreateDescriptorHeap, GetDescriptorHandleIncrementSize (32),
CreateRootSignature, Create{ShaderResource,RenderTarget,DepthStencil}View, CreateSampler, CopyDescriptorsSimple, **GetResourceAllocationInfo**, CreateCommittedResource, CreateHeap, CreatePlacedResource, CreateFence,
GetDeviceRemovedReason, GetCopyableFootprints (computed from the description), CreateQueryHeap; queue Execute/Signal/Wait/timestamps (fences complete when signalled); command list Close/Reset and all recording calls (counted);
resources: buffers are backed by real guest memory so `Map` returns a stable pointer. Slots 3-7 of every D3D12/DXGI object (private data, `SetName`, `GetDevice`) are handled generically; `SetName` is used heavily (a spec gap).
Any slot outside this list is a named fatal. `D3D12_RESOURCE_DESC` offsets used: Width +16, Height +24, DepthOrArraySize +28, MipLevels +30, Format +32.

## Boot milestones (from the traces in `out/`)

Counts are import calls traced (`KH_TRACE`); they vary by a few when thread start-up interleaves differently, the single-threaded prefix is exact (oracle: 1,677 before ManageRun).

* 0..1,676: CRT start-up, 3 `__xi` + 4,653 `__xc` constructors (the C++ static initialisers account for 1,403 `_crt_atexit` calls), WinMain, `axaAppMain`, Steam gate (`SteamAPI_RestartAppIfNecessary` -> false, `SteamAPI_Init` -> true,
  five interface contexts, `ISteamUser::GetSteamID` through the hidden return pointer), `CoInitialize`, `MFStartup`, seven failed `image/dt/kh2_*.hed` / `SettingMenu.hed` opens, then `.nep` stub 0x579bf0 (`ManageRun`) at call-site 0x105474.
* 1,684: `GXDevice.init` (0x11d070) first call (the first GX entry); import call #1,692 is the first import issued from inside the GX extent (`LeaveCriticalSection` at RVA 0x11c19b);
  `createDevices` 0x124060 after 1,725 calls; adapter enumeration 0x10e860 and `D3D12CreateDevice` (ord101) at call-site RVA 0x10e974 after 1,733; game thread procs 0x127ed0 and 0x129110 start after about 2,290.
* Steady state: thread 1012 (0x127ed0, the game main loop) polls `[package+8]` once per millisecond in 0x107240 (guest stack: 0x1072c9 <- 0x106a17 <- 0x1068a2 <- 0x143867 <- 0x13c923 <- 0x14ed52 (`MyApp::vfn1`)
  <- 0x121ded <- 0x127ed9); thread 1016 (0x129110) is the render/present loop (`WaitForVBlank` 60 per second); thread 1004 polls SetupAPI every 500 ms; thread 1008 (StatsMan) waits on a semaphore.
  The 45 s soak run: 105,299 import calls, RSS 71 MB, 0.24 s user CPU, no fault.
* What blocks progress is outside this batch: the package layer (`image/dt/kh2_{first..sixth}.hed`, `image/SettingMenu.hed`) is not served, so the package object is never marked ready (file layer, docs/platform/01-FILE-LAYER.md).

## Oracle check (`tools/oracle_unicorn.py`, report in `out/oracle_report.json`)

Independent Unicorn 2.1.4 emulation of the original exe bytes. Start state = the lifted run's own snapshot after thread set-up (sparse arena pages, TEB/TLS, rsp, Steam objects, host-fn table), the PE image,
the IAT, the fixed CPUID/XGETBV profile applied at the five CPU-identity sites (4 `cpuid` + 1 `xgetbv`). Python stubs mirror 53 imports of the runtime in deterministic mode (`KH_DET=1`: bump allocator with headers, counter clocks,
pid 4242, `_mkdir` succeeds). `_initterm`, `_initterm_e` and `SteamInternal_ContextInit` call back into emulated guest code through a continuation slot.
Compared per call: import name, rcx, rdx, r8, r9 (junk registers included) and the call-site return address; at ManageRun, a CRC-32 of every 4 KiB page of .data/.bss/.shared and of the guest heap (stacks excluded).

* **1,677 of 1,677 import calls identical, 53 distinct imports; 9,335 of 9,335 pages identical** (38 MB of static data plus the heap) at the point where the original reaches the `ManageRun` `.nep` unit.
* The first divergences found along the way were stub inconsistencies, not lifting bugs: (1) call #663 `cosf` was missing from the lifted trace because the lifter's `rt_libm.c` is untraced (fixed in `lifter-rt/rt_libm.c`);
  (2) returns into the host caller differ in representation (sentinel vs continuation slot), normalised; (3) heap block headers and `memcmp` magnitude were runtime details, mirrored/normalised.
* Not covered: anything after ManageRun (shell, GX init, threads), floating-point results of libm calls (xmm0 is not compared), arm64.

## Notes for the lifter owner (ABI observations; no lifter file was modified)

1. `khrt_dispatch.c` resolves only image and import addresses. The runtime needs a third synthetic range for host functions (COM vtable thunks, timer threads, `GetProcAddress` targets). `core.c` is a copy of that file with the range
   added; `kh_dispatch` also stores the target in `g->aux[0]` so one host function can serve many slots. Please fold the range into the shared dispatcher.
2. `hooks.tsv` describes 0x150060/0x150080 as stack-switching yield leaves. They are plain leaf functions that store a field and tail-jump to `0x135470` (`SwitchFiber(from, to)`: if from is the 0x43214321 sentinel it
   calls `ConvertThreadToFiber`, else `SwitchToFiber`). Lifting them normally would be equivalent; the hooks in `threads.c` are byte-for-byte equivalents.
3. `nep_stubs.c` defines an abort stub for every `.nep` unit as a strong symbol; a native shell must replace four of them (`0x579bf0`, `0x579bc0`, `0x579a50`, `0x579ad0`). `tools/gen_nep.sh` filters them out; better: emit weak definitions or accept hook entries for `.nep` units.
4. `rt_libm.c` bypasses the import trace; a traced copy lives in `lifter-rt/` (needed for the oracle).
5. `kh_import_table` order = PE import order and the loader writes `0x7ff7f0000000 + 16*i`; both sides agree. Calls through an IAT slot are direct `rt_imp_*` calls; address-taken slots reach the import range through `kh_dispatch`, so a different base needs no regeneration.
6. G1's "libpng setjmp/longjmp via host" is not implementable (section Services); decide whether PNG error paths may stay fatal.
7. Build: 117 TUs, 0 failures, peak 379 MB each; the link of 40.7 MB with `-rdynamic` is a few seconds.

## Limits and open items

* Everything above is x86-64 Linux, gcc 13, KH_XLATE_MODE 0. arm64 is compile-checked only (no link, no run); the fixed mapping on iOS is unverified (bias mode is the fallback).
* Not exercised yet by the game: fibers (the job system never ran), the two yield hooks in situ, `TerminateThread`, file IO beyond failed opens, any D3D12 recording path (no draw was issued), sound, movies.
* `SleepConditionVariableCS` etc. are not provided (the CRT probes them and falls back).
* Registry values are not persisted; `_chdir` is ignored; `CreateFileMappingA` supports only anonymous mappings (the exit-code mailbox).
* The null D3D12 device never fails; it also never completes a fence that was not signalled (`SetEventOnCompletion` beyond the signalled value is a fatal, since there is no GPU).
