## Overlap report

- Overlaps between any two function ranges or between a range and a CLR IL body: **0** (`overlaps.tsv` has only its header).
- Ranges checked: 48073, belonging to 38455 functions.
- No leaf (no `.pdata`) range touches a `.pdata` range; no two leaf functions share an instruction or a jump table (checked at instruction level during discovery and again by `validate.py`).
- Distinct direct call / jmp targets recorded: every one is a function start (12674 targets, 0 into the interior of another function, 0 into padding or data).
- Every one of the 27,139 base-relocated code pointers and all 20,667 vtable slots point at a function start.
- The only code address taken from inside the image that is not a function start is one `lea` of a catch-continuation label inside the same function (an interior label, not a function).

Tail-merged code (several small entry stubs that all `jmp` to one shared body, e.g. 0x4efe10 / 0x4efe30 -> 0x4efe50) is split into one function per stub plus one function for the shared body: during discovery a jump to a 16-byte-aligned address that follows `int3` padding, or to an address below the function entry, is treated as a tail call, never as an internal branch. This is what keeps the extents disjoint.
