# Movie path: Media Foundation + D3D11 interop in kh2fm.exe, and the AVFoundation replacement

## 1. What the exe does (static analysis)

Functions (all addresses RVA): `0x13da10` open, `0x13dd40` create reader/negotiate, `0x13d500` set output media type, `0x13d260` start/prepare, `0x13e030` audio sample pull, `0x13e350`/`0x13e5a0` seek/stop, `0x13e7f0` per-frame video upload, `0x13ef00` D3D11 device creation, `0x13eb30`/`0x13ec00` timing/helpers, `0x122890` GX-side texture creation + draw for a frame, `0x11c560` NV12 texture helper, `0x13cf90` teardown. Class: `Axa::CCipherMovie` (cipher layer) feeding the reader.

### 1.1 Open (0x13da10)
`FindFirstFileA` existence check -> `MultiByteToWideChar` (wide path, 260 max) -> player object (0x240 B) -> `_open(path, 0x8002 = O_RDONLY|O_BINARY)` and `_read(fd, obj+0x38, 0x100)`: the first 256 bytes of the file are read into the object by the engine's own cipher layer before Media Foundation is used. The files on disk are **not plain MP4**: the first bytes (`3f1ec18b 403621c8 ...`) are not an `ftyp` box, and the 12 KH2 movies share an identical leading block with only a 4-byte field differing. How decrypted bytes reach `MFCreateSourceReaderFromURL` (custom scheme / byte stream / temp file) was **not analysed** (no circumvention analysis; the plan is to run the engine's own cipher code on the owner's files).

### 1.2 Media Foundation setup (0x13dd40)
- `MFStartup`/`MFShutdown`; `MFCreateDXGIDeviceManager(&resetToken,&mgr)`; `mgr->ResetDevice(D3D11 device [obj+0x158], token)` (vtbl 0x38); QI to the manager interface.
- `MFCreateAttributes(&attrs, 3)`; `attrs->SetUnknown(MF_SOURCE_READER_D3D_MANAGER {ec822da2-e1e9-4b29-a0d8-563c719f5269}, mgr)` (vtbl 0xd8); `SetUINT32(MF_READWRITE_ENABLE_HARDWARE_TRANSFORMS {a634a91c-...}, 1)` and `SetUINT32(MF_SOURCE_READER_ENABLE_ADVANCED_VIDEO_PROCESSING {0f81da2c-...}, 1)` (vtbl 0xa8).
- `MFCreateSourceReaderFromURL(wide path, attrs, &reader[obj+0])` (import `MFReadWrite.dll`).
- Stream selection via `reader->SetCurrentMediaType` (vtbl 0x38) per stream (fn 0x13d500): the stream's native type is read (`GetNativeMediaType` 0x28, MAJOR_TYPE `{48eba18e-...}` via `GetGUID` 0x50); **video** (`vids`): output subtype **NV12** `{3231564e-0000-0010-8000-00aa00389b71}`, or `{00000016-...}` = MFVideoFormat_RGB32 when the engine flag at `[.data 0x79cf00]` (checked by `0x105620`) is true (software fallback); **audio** (`auds`): output subtype `{00000003-...}` = **MFAudioFormat_Float** (32-bit float PCM).
- After setup the reader reads `MF_MT_SUBTYPE`, `MF_MT_FRAME_SIZE` (hi = width, lo = height -> `[obj+0x24],[obj+0x28]`), `MF_MT_DEFAULT_STRIDE {644b4e48-...}` (UINT32, fallback 1) and `MF_MT_FRAME_RATE` (num/den; `[obj+0x30] = num/den` as float). `zmovie/en/ena.mp4` (the ending movie) is special-cased by a `wcsstr` that sets byte `[obj+0x34]`.
- Streams: `0xfffffffc` = FIRST_VIDEO_STREAM, `0xfffffffd` = FIRST_AUDIO_STREAM (used in `ReadSample` calls at 0x13e0ea and 0x13e4ef).

### 1.3 D3D11 device for decode (0x13ef00)
`CreateDXGIFactory1(IDXGIFactory4)`; adapter chosen by LUID of the D3D12 device (`[0x13efad]` GetDesc1); `D3D11CreateDevice(adapter, D3D_DRIVER_TYPE_UNKNOWN, NULL, flags 0x820 = VIDEO_SUPPORT|BGRA_SUPPORT, FL {0xb100 11_1, 0xb000 11_0}, ...)` at 0x13f032 (the only D3D11 creation in the exe); multithread-protected presumably (call at 0x13f0a7 vtbl 0x28 with arg 1 = `SetMultithreadProtected(TRUE)` on ID3D11Multithread, unverified).

### 1.4 Per-frame path (0x13e7f0) - D3D11 shared-handle interop
1. `ReadSample` result sample `[obj+0x10]`: `sample->GetBufferByIndex(0)` (IMFSample vtbl 0x140).
2. QI to `IMFDXGIBuffer` (IID at 0x5dd3c0), `GetResource(IID_ID3D11Texture2D 0x5dac50)` (0x18), `GetSubresourceIndex` (0x20), `ID3D11Texture2D::GetDesc` (0x50).
3. First frame only: create a **shared NV12 `ID3D11Texture2D`** with the same desc but width rounded up to a multiple of 256, MiscFlags `SHARED (2)`, ArraySize 1 (`CreateTexture2D`, vtbl 0x28 on the D3D11 device at `[obj+0x158]`); QI `IDXGIResource` (0x5dbde0) -> `GetSharedHandle` (0x40) -> `ID3D12Device::OpenSharedHandle(handle, IID_ID3D12Resource)` (vtbl 0x100, device from accessor 0x11bea0) -> D3D12 resource in `[obj+0x120]`; plus a STAGING copy (Usage 3, CPUAccess READ 0x20000) in `[obj+0x128]` (CPU-readable copy; purpose not determined).
4. Every frame: `ID3D11DeviceContext::CopySubresourceRegion` (vtbl 0x170) from the decoder's texture/subresource into the shared texture with a box (0,0,0,w,h,1).
5. GX side (`0x122890`): create the movie texture(s) through `0x118710` with DXGI format `0x67` (NV12, 2 planes, `0x11c5a1`) / `0x31` R8G8_UNORM and draw with shader pair **45** = VS `0x59ac40` (SV_VertexID quad) + PS `0x5a41b0` (NV12 -> RGB, BT.709 limited range: Y-0.0625, UV-0.5, matrix 1.1644/1.7927/-0.2133/-0.5329/2.1124; t0 = Y plane, t1 = UV plane, alpha 1) with the 1-quad pass `0x10c7e0`.
6. Audio: `0x13e030` calls `ReadSample` on the audio stream (Float PCM); the engine's own mixer consumes it (no XAudio2 calls in the movie extent; the in-engine "sd" mixer is separate - not traced).

MF/D3D11 method census (movie extent, 125 vtable calls; 51 `Release`): IMFSourceReader `SetStreamSelection 0x20`, `GetNativeMediaType 0x28`, `GetCurrentMediaType 0x30`, `SetCurrentMediaType 0x38`, `SetCurrentPosition 0x40`, `ReadSample 0x48`, `Flush 0x50`, `GetPresentationAttribute 0x60`; IMFAttributes `GetUINT32 0x38`, `GetUINT64 0x40`, `GetGUID 0x50`, `SetUINT32 0xa8`, `SetGUID 0xc0`, `SetUnknown 0xd8`; IMFSample `GetSampleTime 0x118`, `GetBufferByIndex 0x140`, `ConvertToContiguousBuffer 0x148`; D3D11 as above.

## 2. What the movies are (read-only, build-host)
`C:\Program Files (x86)\Steam\steamapps\common\KINGDOM HEARTS -HD 1.5+2.5 ReMIX-\STEAM\juefigs\KH2ReSource\zmovie\en\`: **12 files, all `.mp4`**, 1,603,409,392 bytes: ena 667,852,912; opn 237,370,048; sec2 149,234,256; lop 144,665,472; me6 103,381,376; me3 76,252,448; me4 63,308,304; sec 55,570,288; me2 45,884,016; hcb 28,494,128; hca 17,780,048; mea 13,616,096. (Other titles use the same extension: `dt\KH1Movie`, `dt\KHCReSource\BIN\movie`, ~489 `.mp4` in the whole install.) The OpenKH-extracted data tree has **no movie files**. The first 48 bytes of each KH2 file are obscured (not `ftyp`), consistent with `Axa::CCipherMovie`. Because Media Foundation decodes the stream to NV12/Float PCM, the underlying container is MP4-compatible with an MF-decodable video codec (H.264 most likely) and an MF-decodable audio codec (AAC most likely): **codec/profile/resolution/frame rate are unverified** until the plaintext headers are available (run the engine's cipher on a file under the owner's control, or capture `MF_MT_*` at runtime - owner-gated).

## 3. AVFoundation replacement design

Goal: keep the lifted player logic (`CCipherMovie`, timing, `[obj+...]` state) and replace only the reader + texture interop.
- **Source**: provide plaintext MP4 bytes. Options: (a) stream-decrypt with the lifted cipher code into a cache file (`NSCachesDirectory/movie/<name>.mp4`; largest is 668 MB) and open with `AVURLAsset`; (b) `AVAssetResourceLoader` delegate serving decrypted ranges from a custom URL scheme (works for `AVPlayer`; with `AVAssetReader` it is reported to work but unverified).
- **Video**: `AVAssetReader` + `AVAssetReaderTrackOutput(track, outputSettings: kCVPixelBufferPixelFormatTypeKey = kCVPixelFormatType_420YpCbCr8BiPlanarVideoRange (NV12), kCVPixelBufferMetalCompatibilityKey = true, IOSurface-backed)`; AVAssetReader uses VideoToolbox (hardware H.264/HEVC) implicitly. Direct `VTDecompressionSession` only if a custom demuxer is needed. Per frame: `CMSampleBufferGetImageBuffer` -> `CVMetalTextureCacheCreateTextureFromImage` twice (plane 0 `MTLPixelFormatR8Unorm`, plane 1 `MTLPixelFormatRG8Unorm`) -> bind as t0/t1 of shader pair 45 (PS `0x5a41b0`/MSL `msl/nv12_ps_5a41b0.metal`; color range/matrix must match BT.709 limited: if the stream is BT.601 or full-range the original shader would have the same wrongness, keep it).
- **Interop shim**: the D3D11 shared-handle steps disappear. Implement the lifted call surface as: `MFCreateSourceReaderFromURL` -> `AVMovieReader` object; `ReadSample(video)` -> next `CMSampleBuffer` + timestamp (100 ns units to mimic MF); `IMFDXGIBuffer::GetResource/GetSubresourceIndex` + `CopySubresourceRegion` -> a no-op that attaches the CVMetalTexture pair to the shim's NV12 texture object (`0x67`), so `OpenSharedHandle` returns that wrapper. The `GetSharedHandle`/256-alignment stuff and the STAGING copy have no equivalent (the staging copy is only needed if its consumer is found).
- **Audio**: second `AVAssetReaderTrackOutput` with `AVFormatIDKey = kAudioFormatLinearPCM`, 32-bit float, interleaved, native sample rate/channels (to mimic `MFAudioFormat_Float`); deliver buffers to the same consumer the MF path fed (the engine mixer; not traced). A/V timing follows sample timestamps; the engine paces video by frame count using `[obj+0x30]` = fps.
- **Seek/stop** (`0x13e350`, `0x13e5a0`): `SetCurrentPosition`/`Flush` -> recreate `AVAssetReader` with `timeRange`.
- **Memory**: one 2-3 frame CVPixelBuffer pool; the 1080p NV12 frame is ~3 MB.
