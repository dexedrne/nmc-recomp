## Runtime aspect handling and ratios

`mod.yml` lines 9–20 install `engine/ReFined.KH2.dll`, `engine/reFined.cfg` and the Discord SDK. The first is a native x64 Windows plugin. Its initialization registers `HANDLE_ASPECT` at DLL RVA `0x410c8`, pointing at `0x3ca30`. The config file has presentation switches but no aspect setting. The DLL recognizes the command-line switch `-noaspect`, whose initialization branch sets ReFined’s own horizontal margins to +85 and −85 for 16:9. The checkout contains no Lua implementation, C++ aspect source, standalone widescreen patch or ratio-indexed layout pack. The DLL contains a Lua filename for detecting another mod. [Installer](/home/user/work/khnmc-refs/KH-ReFined-KH2/mod.yml:9) · [Config](/home/user/work/khnmc-refs/KH-ReFined-KH2/engine/reFined.cfg)

The handler reads the built width and height from the GX device (+0x10/+0x14), skips zero dimensions, and calculates the ratio from those values. At RVAs `0x3cb74–0x3cc96` it writes a scale equivalent to (W/H)/(16/9) at GX+0x20. Below 16:9 it applies the reciprocal at GX+0x28 and suppresses the final fit-size stores in the PC routine `f_11c1e0`. At 16:9 or wider it restores those instructions and uses 1 at +0x28. At `0x3ccb1` it derives a signed horizontal UI margin from the width at a normalized height of 1080, approximately ceil((floor(1080 W/H) − 1440) × 0.177). It publishes both signs in `ASPECT_INFORMATION`. Multiple parts of the DLL read this shared value. This is evidence for horizontal UI placement, with a 4:3 origin for the margin. It does not establish a uniform resize of every HUD widget. [KHNMC GX field definitions](/home/user/work/khnmc-build/runtime/aspect.c:45)

| Exact ratio | ReFined scale at GX+0x20 | Narrow-fit branch | Meaning for the port |
|---|---:|---|---|
| 4:3 / 16:10 | 0.75 / 0.90 | Yes | Our H1 exposes the taller view. H3 can independently place individual HUD owners. |
| 16:9 | 1 | No | Baseline. ReFined still computes UI margins. KHNMC preserves the PC result. |
| 21:9 / 32:9 | 1.3125 / 2 | No | Both reach the same width-driven path. Real 2560×1080 uses its actual ratio. KHNMC already delegates these shapes to the PC projection. |
| Portrait, e.g. 2007×2853 | About 0.396 | Yes | Arithmetic accepts the dimensions. The horizontal margin becomes negative. This is no evidence of a usable portrait title, HUD or live rotation in ReFined. |

These values are static predictions. This checkout supplies no visual test results for those modes. There is no separate 16:10, 21:9 or 32:9 install choice.

## The two open port tasks

**46b — letterboxed events and subtitles.** A black strip can come from the final fit, a fade, a drawn cinematic bar, or pixels already encoded in a movie. The first three have different owners in this port. H1 addresses fit. Today H4’s `h4_target` extends the four event bars outward while keeping their inner edges fixed, producing extra black above and below a tall frame. Its other three objects are genuine full-screen fades. The smaller implementation is to change only the event-bar cases reached from `f_156e20` in narrow fill. Try a thin matte at the outer edges with the PC fraction of picture height, and compare with suppressing the matte on the same shot. Judge both the actors’ framing and readability over a bright scene. A movie with baked-in bars needs a separate media decision. [H4 objects and geometry](/home/user/work/khnmc-build/runtime/aspect.c:886)

Use a frame with the bars visible **and a two-line subtitle**. Log the text owner, glyph bounds and scissor through entry, steady state and exit. Start with the PC text size and centred safe width. If the new matte clips the second line or leaves the text unreadable, move only that event-text owner to a bottom-safe baseline with PC line spacing. H3’s default centre is the safe starting point. A generic SpriteMessage adjustment would also move unrelated UI. Compare the same shot at 1920×1080, 1920×1350 and 2007×2853, plus a fade to black and a full-frame event as controls. Z40’s routes never displayed an event with bars, and F46’s centred talk windows are different evidence. No ReFined file inspected supplies an independently verified subtitle anchor or fixes off-camera set edges in every shot. [Z40 coverage limit](/home/user/work/khnmc-build/implementation notes:320) · [F46 talk windows](/home/user/work/khnmc-build/implementation notes:86)

**47 — live rotation.** ReFined demonstrates the value of reading current render dimensions when computing a margin. This checkout supplies no iOS orientation handling, swap-chain rebuild, or atomic transition between the old and new render targets. Use the shell’s drawable resize to drive the existing PC window/ResizeBuffers path, then let H1/H3/H4/H7 and the title and zoom logic read the new dimensions. A landscape → portrait → landscape round trip with a pause overlay up will expose a stale captured frame, old scissor or cursor scale that a fresh launch cannot reveal.
