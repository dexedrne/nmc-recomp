# D3D12 / DXGI shim interface spec (Stage 1: D3D12-on-Metal under the lifted GX code)

Header-style interface: `shim/d3d12_shim.hpp`. Machine-readable table with per-method evidence: `d3d12_shim_methods.json` (75 methods on 19 interfaces + 3 free functions; the gate notes' "~65 methods on ~15 interfaces" is confirmed in magnitude, the exact figure depends on how the untyped offsets are resolved).

## 0. Method of the census and how to read the counts

Scanned every `call [reg+off]` in the GX extent 0x109000-0x12a000 (622 indirect vtable calls; 205 are `Release`) and in the movie extent 0x13cf00-0x13f400 (125) with a linear-sweep disassembly (capstone with SKIPDATA; the earlier S1 scans stopped at the first undecodable byte near 0x1121xx and under-counted) and a backward slice (`tools/comsites.py`) that resolves the object expression. `typed_sites` = number of sites whose object provably comes from a known origin (the command-list accessor `0x11bb30`, or a known `GXDeviceImpl` field: device `+0x2e0`, swapchain `+0x468`, queues `+0x470/+0x488`, allocators `+0x4a0/+0x4b8`, command lists `+0x498/+0x4b0`, heaps `+0x4e0/+0x4e8/+0x4f8/+0x808`, adapter `+0x4d0/+0x4d8`). Entries with a string like "S1: N offset sites" carry the old per-offset count (any vtable with a method at that offset, so inflated) and are lower-confidence. Many GX-internal virtual calls (class vtables of `GXDevice::*`) share these offsets and are excluded wherever the object origin could be resolved.

Corrections to the S1/verification tables found here: `IDXGISwapChain1::GetFullscreenDesc` (0x98) not ResolveSubresource (confirmed); `ID3D12Device::GetCopyableFootprints` (0x130) not SetGraphicsRootConstantBufferView (confirmed; the cmdlist CBV sites are separate); command-queue vtbl 0x80/0x88 are `GetTimestampFrequency`/`GetClockCalibration` (not Wait; `Wait` is 0x78); `ResolveSubresource`/`CopyResource` live in `0x1253d0` and are chosen by sample count.

## 4. Fixed configuration the shim can hard-wire

- **Root signature** (fn 0x11df90, version 1, flags 1 = ALLOW_INPUT_ASSEMBLER_INPUT_LAYOUT, 0 static samplers): params 0,1,2 = root CBV b2, b3, b4 with visibility VERTEX; param 3 = root CBV b6 PIXEL; param 4 = descriptor table with one SAMPLER range (s0) PIXEL; params 5,6 = descriptor tables with one SRV range each (t0, t1) PIXEL [verification: the builder had 4,5 = SRV and 6 = sampler].
- **Descriptor heaps**: RTV 320, DSV 320 (CPU only); CBV_SRV_UAV 16384 shader-visible (a free-list slab object of 0x810 B at `dev+0x4f0`: handle increment cached in its first dword, heap at +0x808, 256 qwords of 0xff.. bitmap); SAMPLER 8 shader-visible.
- **Samplers** (8): `{Filter 0x15 LINEAR | 0x55 ANISOTROPIC} x {U WRAP|CLAMP} x {V WRAP|CLAMP}`, W WRAP, MaxAnisotropy 0|4, ComparisonFunc NEVER, MinLOD 0, MaxLOD ~FLT_MAX (value at 0x5a9cd0). Order of creation: outer loop U, then V, then filter (ebx 0 = linear, 1 = aniso); param-6 table selects one of the 8 slots.
- **Swapchain**: B8G8R8A8_UNORM, 3 buffers, FLIP_DISCARD, flags ALLOW_MODE_SWITCH|FRAME_LATENCY_WAITABLE_OBJECT, usage RENDER_TARGET_OUTPUT|BACK_BUFFER; window mode only drives resize via ResizeBuffers(3,w,h,0x57,0x42) and SetFullscreenState([dev+0x416], NULL).
- **MSAA**: sample count chosen at start by `CheckFeatureSupport(MULTISAMPLE_QUALITY_LEVELS)` over 8,4,2,1 for B8G8R8A8 (stored `[dev+0x454]`, default 1, written to RT-set records); resolve is an explicit `ResolveSubresource(dst,0,src,0,0x57)` (or `CopyResource` at 1x) in fn 0x1253d0. Under Metal: Apple GPUs support 1/2/4; clamp 8 to 4.
- **Command lists**: one DIRECT list per queue, recorded then `Close`d and `ExecuteCommandLists(1, &list)`; allocators `Reset` per frame; a second allocator/list pair exists only when the adapter VendorId is 0x1002 (AMD).
- **Fences**: one `ID3D12Fence` per queue, wrapped by fn 0x116e00 (CPU wait via event; waitable swapchain object for frame pacing).
- **Resources**: placed/committed textures with explicit transition barriers (state tracked in the GX resource object, `[resource+0x10]` word, immediates RENDER_TARGET/DEPTH_WRITE/PIXEL_SHADER_RESOURCE/COPY_DEST/GENERIC_READ), upload-heap buffers with persistent maps for the CBVs and vertex/index data, query heaps for timestamps, readback buffers (state COPY_DEST).

## 5. Metal mapping design

1. **Objects**: each COM class is a small C++ object with the real vtable offsets (see header comment); `QueryInterface` supports exactly the IIDs listed. Handles (descriptors) are 64-bit indices/pointers into shim-owned arrays, so `GetCPUDescriptorHandleForHeapStart` + `n * increment` arithmetic done by the lifted code stays valid (use increment = 1 or 32).
2. **Fixed binding layout, no argument buffers needed**: because the root signature is one fixed shape, do not use Metal argument buffers in v1. Map root CBV params 0..3 to `setVertexBuffer/setFragmentBuffer` at buffer indices 2,3,4 (VS) and 6 (PS) with the GPU-VA -> (MTLBuffer, offset) lookup, and the 3 tables (param 4 = sampler, 5 = t0, 6 = t1) to `setFragmentSamplerState(0)` and `setFragmentTexture(0/1)`. Per-draw dirty tracking replaces `SetGraphicsRoot*`. (If descriptor-heap semantics must be preserved verbatim, an argument-buffer encoding of the 16384-entry SRV heap needs Tier 2 argument buffers; not required by this exe.) Metal vertex-buffer slot for the IA buffer: pick a high index (e.g. 20) so it does not collide with 2..6.
3. **Fake GPU virtual addresses**: `GetGPUVirtualAddress` returns `(bufferId << 40) | offset`; the shim keeps `bufferId -> MTLBuffer`. `SetGraphicsRootConstantBufferView(param, va)` then costs a table lookup.
4. **PSO**: `CreateGraphicsPipelineState` receives the full 0x290-byte desc; key it by (VS ptr, PS ptr, blend desc, write mask, sample count, input layout, topology type) -> `MTLRenderPipelineState`; depth/stencil/cull/front-face go to `MTLDepthStencilState` + encoder state at `SetPipelineState`. Keep the key table from PSO-KEY.md as the cache key so the lifted code and shim agree.
5. **Heaps / residency**: texture suballocator (fn 0x1145b0) uses `CreateHeap`+`CreatePlacedResource`; map to `MTLHeap` with `makeTexture(descriptor:offset:)` (Metal 3, aliasing allowed) or simply ignore placement and allocate textures individually; residency calls (`MakeResident`/`Evict`) are not used by this exe. Budget: replace `QueryVideoMemoryInfo` with `os_proc_available_memory()`; the texture heap budget logic at 0x124b50 consumes it.
6. **Fences**: `ID3D12Fence` -> `MTLSharedEvent` (CPU wait via `waitUntilSignaledValue:timeoutMS:`, `SetEventOnCompletion` via `notifyListener`); `Signal/Wait` on queues -> `encodeSignalEvent/encodeWaitForEvent`. The waitable swapchain object -> a `dispatch_semaphore_t` initialised to the max latency and signalled from `addCompletedHandler`.
7. **Barriers**: translate to nothing except (a) transitions into/out of COPY_DEST/COPY_SOURCE around blit passes (insert pass boundaries), (b) RESOLVE: end the render pass with `MTLStoreActionMultisampleResolve` into the resolve texture, (c) transitions on the back buffer to PRESENT (end of frame: present drawable).
8. **Upload semantics**: `CopyTextureRegion` from an upload buffer needs D3D12 row pitch (256-aligned) because the game fills rows itself from `GetCopyableFootprints`; return those footprints, then use `MTLBlitCommandEncoder copyFromBuffer:...`. Block-compressed textures (BC3) need the 4x4-block row math; on Apple GPUs BC support is only on newer families (A15+? unverified) so plan on offline ASTC conversion and a format substitution in `CreateCommittedResource/CreatePlacedResource` (and in `GetCopyableFootprints` results).
9. **Timestamps**: map query heap to `MTLCounterSampleBuffer` where supported, else return monotonically increasing fake values; `GetTimestampFrequency` = 1e9.
10. **Present**: `Present1(sync, flags)` -> `presentDrawable` + commit; `GetBuffer(i)` returns the texture wrapper of the i-th acquired drawable (a 3-slot ring; rendering to a swapchain image that is not the current drawable must be avoided: acquire lazily at the first RTV bind of the frame).
