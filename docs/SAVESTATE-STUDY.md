# Task 58 — Exact save states for the lifted port

A save state needs a consistent cut across guest memory, execution, host services and GPU work. The first prototype should capture one reproducible frame boundary on the null backend and restore into a fresh runtime with the same build and content. A memory-only dump cannot recover an executing native call stack or device-owned contents.

Study only. No builds or device measurements. Capture rates and the proof of exactness require instrumented runs.

## What “exact” buys the player

Return to the saved game frame with the same held buttons, pending work, voices and rendered history. Given the same subsequent input samples, external clock readings and scheduling decisions, the next frames must agree byte for byte with uninterrupted play on the same backend. The first supported configuration should be one build, one content manifest, one clock policy and one backend. Live play branches at the first new input. Sound already played and pictures already scanned out belong to the past.

**Feasibility decision.** Prove a fresh-process return through the lifted callers and a suspended fiber before investing in GPU capture. The port executes nested native calls. A function RVA and a register dump alone cannot restart them. The smaller experiment is a same-process freeze and thaw, which tests the barrier but loses the state if iOS terminates the app. A durable slot needs the following work.

**How to restart execution.** Instrument the frame call sites and each live worker at a candidate cut. Enumerate the lifted callers, host imports/callbacks on the stack, inactive fibers, native temporaries live across each yield and their guest return sites. For the supported paths, generate/implement explicit resume labels and typed continuation records up to a runtime dispatcher. A frame-boundary wrapper nested beneath a game loop still needs that loop's continuation. Allow a worker to finish an import, or replace its wait with a serializable wait record before parking. Reattach fresh TLS and thread/fiber owners without rerunning guest attach/init callbacks. A fiber asleep inside an unconverted call chain disqualifies the entire cut. If the reachable chains cannot be bounded on a field route, budget a resumable lift/dispatcher as a separate prerequisite. Raw native stacks contain ASLR-dependent return addresses, host pointers and possibly authenticated addresses on Apple.

## Graphics inventory and reconstruction

Use the phone's wrapped route, KHNMC_GFX=vkd3dw, as the interception surface. The identity/x86 trampoline hands out raw host interfaces and bypasses comprehensive per-method capture. The wrapper already marshals method arguments, but returns real descriptor handles, GPU VAs, and host-minus-bias addresses for Map and blob pointers. It also forwards AddRef/Release and keeps real→guest identity. Bundles record real pointers. The existing frame dumper reads only a presented color buffer. These facts set the minimum scope of GPU work. See runtime/gfx_wrap.c:1–44,334–539 and runtime/gfx_vkd3d.c:1–41; project report runtime/win64/implementation notes.

## On-demand consistent cut

1. Latch a foreground request with a generation number. Let running work advance to the next eligible *game* frame. Place a candidate marker before the counter/input/route mutations in f_105e10 (runtime/null_input.c:89–105). Pair it with a completed graphics frame serial, the timing thread f_1287d0 and frame semaphore handoff. A Present count alone can advance independently. Record exactly which side of input sampling and frame release the cut represents.
2. Close admission of **new** frame work at the producer boundary. Permit outstanding dependencies to finish. Each registered worker/fiber reports its logical park reason, serializable continuation and epoch with zero unrecorded locks/callbacks. In the loader, f_3a0c60 takes a node from 0 to 1, releases the list lock during read/postprocess and publishes state 2. Finish state 1, then park before the next claim. A state-2 callback can remain pending with its list order saved; never deliver it during both capture and restore. f_3a0790 consumes it on the game thread. Apply the same admission/count rule to independent audio streams. See runtime/bgload.c:3–27.
3. Let already-due timer, mixer pass and guest callback work reach the agreed cut. Park mixer and output consumer between quanta/pulls. Close input delivery, preserve queued samples and freeze logical clock advancement. Do not hold a mutex needed by another participant while waiting. If progress requires another game frame, abandon this candidate and retry at the next eligible frame. Bound requests and report the blocking thread, object or queue.
4. Reuse Task 41's **graphics admission and drain primitives**: zero admitted calls, all registered queues fenced and completed, zero pending presenter slots, fence callback handoffs accounted for. Its normal suspend path also changes focus, posts minimise, stops audio and neutralizes held pads. A quicksave needs its own coordinator so these changes never enter the saved timeline. Its timeout paths deliberately permit an incomplete drain. Any late/failed/unsupported drain disqualifies the cut. Serialize lifecycle requests with the cut; backgrounding revokes foreground GPU work, cancels the capture and hands gate ownership to lifecycle. See runtime/app_life.c:115–161 and project report runtime/win64/implementation notes.
5. Check all acknowledgments against the same epoch, no active mutators, unclassified objects or uncommitted completion edges. Under exclusive foreground admission run only the coordinator's readback commands with private fences. Keep the first prototype stopped through streaming the file. Validate version/lengths, section checksums and completion footer; sync a same-directory temporary file and atomically replace the slot, syncing directory metadata where supported. An interruption, disk-full or timeout keeps the last good slot. Release gates in dependency order and rebase clock origins.
6. On load preflight build/lift ABI, executable/mod/assets, graphics profile, page/layout and all section limits before altering live state. Restore in clean initialization mode with workers/devices held; recreate pages, identities, host objects, dependencies, queues and continuations. Validate counts and digests before allowing one frame token. Report an invalid slot or unsupported state explicitly; a failed restore must not fall through to partially initialized gameplay. On a memory-limited phone preflight first, then restart into the validated slot with a clean-boot recovery path.

## A20 / 12 GB phone budget

There are useful **Mac route measurements**. The title run reports 890 MiB committed in the ID zone and 0 MiB far. The story run reports 1,178 MiB committed (1,137 MiB in use) and 0 MiB far. Adding the approximately 45 MiB image/slack mapping gives roughly **935 MiB and 1,223 MiB of readable CPU ranges** in those two cuts before zero elision. These exit readings are examples, not phone measurements or maxima. GPU/driver allocations are outside these heap counts on the wrapped backend. See run-mac-gfx/mac-v36title/run.out:3384–3385 and run-mac-gfx/mac-k37story-gpu/run.out:25508–25509.

Slot bytes = stored nonzero guest chunks + authoritative GPU payloads without duplicate aliases + logical runtime/audio/continuation records + manifest/index. At 2853 × 2007, three 4-byte color backbuffers alone are about 65.5 MiB before compression, depth, mips, or other render targets. Storage depends on scene and reuse. As a sizing example, a **1.5 GB slot** needs 4.5 GB for three retained slots and about 6 GB at peak while replacing one. Use decimal MB for I/O and binary MiB for the arena measurements above.

| Hypothetical sustained write / cold read (MB/s) | Write 1,500 MB | Read 1,500 MB |
|---|---:|---:|
| 150 / 300 | 10 s | 5 s |
| 300 / 500 | 5 s | 3 s |
| 500 / 750 | 3 s | 2 s |

These are arithmetic scenarios, not A20 benchmarks or implementation estimates. End-to-end pause adds wait for a cut, GPU transitions/copies/fences, memory scan/encoding and durable sync. Load adds validation, decoding, object/PSO rebuild, upload/fences and release to first playable frame. Compression helps only if the encoded path is faster end-to-end. The 12 GB is shared system RAM. Budget the existing game/device footprint plus bounded staging, encoder and index buffers; a second full arena, GPU duplicate, or whole-slot RAM buffer risks termination. Start with one reusable 8 MiB CPU chunk and a bounded GPU staging allocation sized for the largest supported copy footprint, subdividing where legal. Capture committed/encoded/readback bytes, storage free space, peak physical footprint and OS memory pressure for title, field and battle. On the phone measure bytes / elapsed for write through sync and for cold read separately, plus request→cut, cut→resume and load→first playable frame. Report medians/maxima over five trials per scene with screen size and thermal state. A sustainable hardware rate and peak slot size remain open.

## Staged prototype and proof

Use an opt-in path throughout. The control runs the same exact-mode clock and scheduler with capture disabled. Use integer frame serials and fixed inputs. Frame-clock mode alone still allows pthread races. Record/replay guest-visible nondeterministic events or impose deterministic wake/dispatch ordering wherever the control diverges. Equal screenshots alone cannot prove a rewind.
