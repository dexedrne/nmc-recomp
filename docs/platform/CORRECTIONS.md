## Errors found and fixed
1. **Steam run gate (04-STEAM-FACTS 4.3/4.4, README headline 4, platform_seams.json, steam_surface.json, t4_steam.py, name_proposals.csv/names_csv.py; same wording as G1 section 4 item 2).** The docs said `0x105420` calls `ManageRun` (0x579bf0) only if state 0x8cc420 == 1. Disassembly: 0x105420 starts with `cmp [0x79cfa0],0 ; jne 0x105471` and 0x105471 is the `call 0x579bf0`. The state compare (0x105468) exists only on the path that creates the platform object. That path stores the new object pointer regardless of the return value of 0x14d610 (0x105461). Before the gate call (0x14f4a7) `axaAppMain` already calls 0x104a60 (0x14f25d) and 0x1044d0 (0x14f308), which have the same prologue and write 0x79cfa0 (only writers: 0x1044d0, 0x104a60, 0x105420, 0x105540, deleter 0x105380 with callers 0x101860/0x101930 only). So in the code's boot order the state test inside 0x105420 is not evaluated. Same for 0x105540 (returns true when the object exists) and the language functions (they skip the state test when the object exists and cope with a null ISteamApps). Fixed text now states the creating-path-only condition. Reachability of 0x14f25d/0x14f308 was not path-checked. This is a facts correction only; nothing here designs or suggests a bypass.
2. **Stick order (03-INPUT 3.2, khnmc_input.h RawPadState, input_surface.json).** The docs put the left stick at GamePad+0x20/+0x24 and the right at +0x28/+0x2c. In 0x134d10 the first stick conversion reads XINPUT_STATE sThumbRX/RY (state+0xc/+0xe) and its result is stored at +0x20/+0x24; the second reads sThumbLX/LY and stores at +0x28/+0x2c. This matches the PS2 pad byte order (PADDATA bytes 2..5 = RX, RY, LX, LY via 0x133e00/0x132b50). Fixed: +0x20 rx, +0x24 ry, +0x28 lx, +0x2c ly. The GCController mapping in the doc (left thumbstick -> lx,ly by name) stays right as long as fields are addressed by name, not offset.
3. **Remastered directory count (01-FILE-LAYER 1.3.4, platform_seams.json).** "390 game-file directories" is wrong: there are 293 game files with a remastered folder (224 + 69, as the validation section already says) and 390 directories that directly contain files, of which 97 are nested audio-slot directories.
4. **Wording (03-INPUT 3.1).** "11 + 4 functions" for HID/setupapi means 11 + 4 imports; they are called from 10 functions.
